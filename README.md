## 프로젝트 소개

서울에는 다양한 관광지와 문화시설 정보가 존재하지만,  
장소 정보와 실제 방문자의 경험을 한 번에 확인하기는 어렵습니다.

서울로그는 서울 공공데이터를 기반으로 장소를 탐색하고,  
AI 챗봇을 통해 상황과 취향에 맞는 장소를 추천받으며,  
해당 장소를 방문한 사용자의 경험을 익명 게시글로 확인할 수 있는 서비스입니다.

### 핵심 사용자 흐름

1. 홈에서 최신 게시글과 인기 게시글을 확인합니다.
2. AI 챗봇에 원하는 장소나 활동을 자연어로 입력합니다.
3. 챗봇이 서울 공공데이터에서 적합한 장소를 추천합니다.
4. 추천 장소를 선택하면 해당 장소가 태그된 커뮤니티 게시글을 확인합니다.
5. 사용자는 방문 장소를 태그하여 자신의 경험을 게시글로 공유합니다.

## 기술 스택

### Frontend

- Vue 3 (Composition API)
- TypeScript
- Vite
- Vue Router

### Data & Storage

- TourAPI 4.0 기반 서울 공공데이터 JSON
- Browser `localStorage`
- 별도 백엔드 서버 없음

### AI

- OpenAI API
- `gpt-5-mini`
- Structured Output 기반 추천 결과 생성

## 트러블슈팅

### 1. 프로젝트 구조와 협업 기준 부재

#### 문제
초기에는 Vue Router와 공통 폴더 구조가 정리되지 않은 상태에서 기능별 개발을 시작해 페이지 연결과 파일 관리 과정에서 혼선이 발생했습니다. 팀원별로 수정하는 파일 범위가 겹치면서 통합 시 충돌 가능성도 높아졌습니다.

#### 해결
먼저 라우트 구조와 공통 디렉터리 역할을 정리하고, `feature/ai`, `feature/community`, `feature/ui`처럼 기능별 브랜치를 나누어 작업했습니다. 또한 다른 팀원의 담당 파일을 수정하기 전에는 Mattermost를 통해 변경 목적과 범위를 공유했습니다.

#### 배운 점
기능 구현을 빠르게 시작하는 것보다 초기 프로젝트 구조와 협업 규칙을 먼저 합의하는 것이 전체 통합 비용을 줄이는 데 중요하다는 점을 배웠습니다.

---

### 2. OpenAI API 환경변수 인식 오류

#### 문제
`.env` 파일에 API 키를 입력했지만 Vite 클라이언트에서 환경변수를 읽지 못해 AI 추천 기능 호출이 실패했습니다.

#### 원인
Vite에서는 클라이언트에서 사용할 환경변수 이름에 `VITE_` 접두사가 필요하지만, 초기에는 해당 규칙이 적용되지 않았습니다.

#### 해결
환경변수 이름을 아래와 같이 변경했습니다.

```env
VITE_OPENAI_API_KEY=발급받은_API_키
